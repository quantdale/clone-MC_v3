# Design: 176-nether-world-generation

## Context/current state
- 088's `generateTerrainColumn` established the terrain-column shape (pure, seeded, sparse
  `TerrainColumn` over a 16×16×height volume) with an overworld density model (surface landmass +
  water + bedrock floor). 175 defined `NETHER_DIMENSION_TYPE` (0..255, no skylight, ultrawarm).
- 176 is the first dimension-specific generator: same output shape, Nether rules.

## Target state
- `src/worldgen/NetherTerrain.ts` holding the Nether config/ids defaults and
  `generateNetherColumn`.

## Invariants
- Defaults: `minY 0`, `maxY 256` (175's Nether bounds), `lavaLevel 31`, `ceilingY 127`; config
  validation requires `minY < lavaLevel < ceilingY < maxY` (all integers).
- Bedrock at exactly `minY` (floor) and `ceilingY` (roof) for every (x, z) in the column; cells
  above `ceilingY` are air.
- No cell is ever the water id (8); every cell with `minY < y < lavaLevel` is non-air
  (netherrack where density > 0, else lava).
- Density: `(lavaLevel − y) / 64 + noise(y)` with `noise ∈ [−1, 1]` from the seeded 3D value noise,
  so the terrain is mostly solid at the lava line, cavernous above (air pockets in 32..126), and
  empty at/beyond ~`lavaLevel + 64` — always below the roof.
- Deterministic per (seed, columnX, columnZ); identical inputs → identical columns.

## API and data model
```ts
// src/worldgen/NetherTerrain.ts (new)
export interface NetherTerrainConfig {
  worldSeed: number;
  minY: number;        // 0
  maxY: number;        // 256
  lavaLevel: number;   // 31
  ceilingY: number;    // 127
}
export interface NetherTerrainBlockIds { netherrack: number; lava: number; bedrock: number; }
export const DEFAULT_NETHER_TERRAIN_CONFIG: Omit<NetherTerrainConfig, 'worldSeed'>;
export const DEFAULT_NETHER_TERRAIN_BLOCK_IDS: NetherTerrainBlockIds;
export function generateNetherColumn(
  seed: number,
  columnX: number,
  columnZ: number,
  config?: Partial<NetherTerrainConfig>,
  ids?: Partial<NetherTerrainBlockIds>,
): TerrainColumn;
```

## Control/data flow
1. A future wiring change (or 177-178's portal destination) calls `generateNetherColumn(seed, cx,
   cz)` per column, exactly as 088's overworld column is consumed today.
2. The returned `TerrainColumn` is sparse (non-air cells) with the same lookup API, so existing
   column-loading code accepts Nether terrain unchanged.

## Detailed behavior
- The density field is centered on the lava level so the Nether's structure is a lava-ocean floor
  rising into caverns — the faithful vanilla silhouette (lava at the bottom, terrain above, open
  roof space) rather than a solid overworld-style landmass.
- The full bedrock roof at 127 is vanilla's Nether ceiling; 128..255 stays air (the open roof area
  above the ceiling).
- Block ids are parameters exactly like 088's `TerrainBlockIds`: `lava: 20` and `bedrock: 7` match
  the registry today; `netherrack: 1` is a documented placeholder until 179 registers the real
  netherrack block (callers pass the real id).

## Failure modes
- Invalid configs throw a descriptive `Error` before any generation; invalid ids throw similarly.
- The generator never throws for valid inputs and never emits out-of-range cells (`TerrainColumn`
  bounds them by construction).

## Compatibility/migration
- One new worldgen file; zero registry changes; no `Game.ts` edit; no schema/save-format change.

## Performance/resource constraints
- One column = 16×16×256 = 65 536 cell evaluations with O(1) noise per cell (~0.5 ms/column in
  tests); identical cost profile to 088.

## Testing seams
- Tests use the real `TerrainColumn` and `NETHER_DIMENSION_TYPE`; assertions are structural
  (floor/roof/no-water/lava/non-air-below-lava/determinism/custom-ids) rather than golden hashes.

## Observability/debugging
- `TerrainColumn.blockCount` and per-cell lookups make generated columns inspectable; the default
  config constants are exported.

## Affected files/symbols
- `src/worldgen/NetherTerrain.ts` (new).
- Tests: `tests/unit/NetherTerrain.test.ts` (new). No other files.

## Rejected alternatives
- **Golden-hash assertions**: rejected — structural invariants pin the *rules*; hashes would pin a
  specific noise shape that 179+ may legitimately refine.
- **Adding netherrack/basalt blocks now**: rejected — that is 179's content baseline; parameterized
  ids keep 176 a generation-only change (the 088 precedent).
- **Reusing `generateTerrainColumn` with Nether config**: rejected — the density model differs
  fundamentally (spongy vs landmass); a dedicated generator is clearer than overloaded parameters.

## Downstream dependencies
- 177-178 (portal blocks/linking) open into columns generated by this module; 179 (Nether content)
  registers netherrack and passes its real id; 181+ (End) mirrors this module with End rules.
